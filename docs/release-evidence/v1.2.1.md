# Store v1.2.1 release evidence

Date: 2026-08-24

- Hotfix branch: `hotfix/v1.2.1-admin-publish-posture`.
- Scope: admin repository publish recovery, product preview console cleanup,
  multiline event addresses, and production-posture issue #50.
- Previous independently reversible release: `v1.2.0`.

## Incident evidence and fixes

- The production archive request returned `502` with `Unable to reach GitHub`.
  The bounded shared GitHub transport uses that response only for a thrown
  outbound request; configured GitHub secret names were present, and a later
  repository-backed media listing succeeded. This is consistent with a
  transient transport failure rather than missing credentials or an invalid
  archive status.
- Post-release correction: a live v1.2.1 trace and same-runtime reproduction on
  2026-08-25 proved the request was failing locally because Cloudflare Workers
  rejects `redirect: "error"`. Store v1.2.2 and Platform v0.34.1 supersede the
  earlier transient-failure inference while retaining the v1.2.1 retry and
  reconciliation safeguards.
- Repository reads now make at most three bounded attempts for retryable
  transport, timeout, invalid-response, rate-limit, or 5xx outcomes. A single
  file write with an ambiguous outcome reads the current file before retrying:
  exact desired content is reconciled as success, unchanged expected content
  may be retried, and a different SHA/content returns a conflict.
- The preview removes scripts and active handler URLs before injection, runs in
  an opaque sandbox, and no longer requests Google Fonts outside the deployed
  CSP. The existing Store stylesheet and allowed Typekit face remain.
- Event addresses use a two-row textarea. Browser coverage proves line breaks
  survive editor loading, lookup remains beside the field on desktop, and the
  control stacks without overflow on a 390-pixel viewport.
- Issue #50 traced to the scheduled audit reading localhost-safe tracked
  Wrangler defaults. The workflow now generates production-shaped config in
  its disposable checkout, while provider targeting independently prioritizes
  canonical production origins.

## Protected merge and deployment gates

The hotfix must pass the canonical `npm run test:premerge` gate on its reviewed
commit before merge. Production deployment must use the resulting immutable
`v1.2.1` tag. After deployment, the release operator must verify the Worker
version, public/admin response posture, a clean preview console, and a successful
manual Production Posture run before closing issue #50. No live product status
mutation is required for release verification; archiving a real product remains
an explicit administrator action.
