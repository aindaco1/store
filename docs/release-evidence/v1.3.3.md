# Store v1.3.3 release evidence

Date: 2026-08-27

- Candidate branch: `release/v1.3.3-admin-email-filters`.
- Scope: constrained post-event email authoring refinements, expired-session
  recovery, canonical product filters for Orders and Analytics, and roadmap
  updates.
- Previous independently reversible release: `v1.3.2`.
- Shared dependency: Dust Wave Platform `v0.34.1` at
  `ae380c43a16af352ae946f47dd1b7aa4e5b093f0`.

## Behavior and administration contract

- English and Spanish post-event mission fields share one constrained editor
  pattern for bold, italic, underline, and sanitized links. Delivery and preview
  continue to use the same renderer and safe-link policy.
- The settings layout gives numeric controls only the space they need, preserves
  readable labels, removes the synthetic preview recipient, and renders the
  preview against the delivered email's white background.
- A `401` from an authenticated dashboard request clears only in-memory session
  state and returns the browser to the existing sign-in panel. Authorization,
  CSRF, origin, role, and scope enforcement remain Worker-owned.
- Orders and Analytics accept one canonical product identifier. Filtering is
  applied by the Worker, product options include current catalog and historical
  order products, and Orders CSV exports inherit the same filter.
- Product-scoped Analytics derives revenue from matching persisted line-item
  subtotals so a mixed order is not wholly attributed to the selected product.
- Customizing additional Store emails and filtering Analytics by delivery type
  remain roadmap items and introduce no runtime behavior in this release.

## Candidate verification

- JavaScript syntax, localization validation, production Jekyll build, and
  `git diff --check` passed.
- Generated asset budgets passed at 512,196 JavaScript bytes and 196,938 CSS
  bytes; `admin.css` remains within its focused 115,000-byte limit at 114,879.
- The complete unit suite passed 497 tests across 102 files. Focused cache,
  analytics, and endpoint coverage passed 34 tests.
- The complete Chromium admin browser suite passed 16 tests, covering desktop,
  Spanish tablet, mobile Orders, 200% text scaling, and expired-session recovery.
- Local Podman pre-merge execution remains unavailable while another project's
  VM owns the machine's Apple virtualization slot; that unrelated VM was left
  undisturbed. Protected **Merge Smoke** is required on the exact candidate
  commit and supplies the containerized pre-merge gate.

## Ethical review

- Product filters operate only on authenticated private admin reads and do not
  create new customer data, tracking, profiling, or broader export access.
- Session-expiry recovery improves clarity without weakening the canonical
  authorization boundary or retaining expired credentials.
- Email editing remains constrained and sanitized, with separate authored
  languages, plain-text parity, recipient deduplication, suppression, timing,
  and delivery idempotency unchanged.
- Roadmap additions are explicitly non-shipping plans.

## Release sequence

1. Push the candidate branch and require protected **Merge Smoke** on the exact
   commit.
2. Merge the reviewed candidate to `main`, create immutable tag `v1.3.3`, and
   dispatch **Deploy Production** with that tag.
3. Verify the deployed Worker version/configuration, public assets, private
   admin response policy, and production posture.
4. If acceptance fails, redeploy immutable tag `v1.3.2`; do not roll back
   canonical orders, fulfillment, inventory, or email delivery state.
