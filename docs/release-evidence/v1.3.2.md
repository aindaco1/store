# Store v1.3.2 release evidence

Date: 2026-08-26

- Candidate branch: `fix/post-event-email-settings-preview`.
- Scope: clearer post-event configuration, explicit bilingual mission editing,
  and a live delivery-faithful email preview.
- Previous independently reversible release: `v1.3.1`.
- Shared dependency: Dust Wave Platform `v0.34.1` at
  `ae380c43a16af352ae946f47dd1b7aa4e5b093f0`.

## Behavior and administration contract

- The global post-event delay remains active and determines eligibility at
  event end plus the configured 1–720 hours. Product activation must still
  occur before that cutoff, which remains locked in the browser and Worker.
- Post-event mission copy uses the dashboard's constrained rich-text editing
  pattern. English and Spanish are stored separately; the Store does not
  invent or automatically translate Spanish copy.
- Support URL fields use three quarters of their desktop row and suggested
  amount fields use one quarter, while narrow screens retain a single column.
- The preview updates from unsaved settings without a refresh action, uses the
  same HTML renderer and inline styling as delivery, and presents sender and
  subject metadata as an email envelope.
- The sample selector includes only non-test ticket or RSVP products with the
  post-event feature enabled. Server validation enforces the same boundary.
- The internal copy-version identifier remains available to delivery logic but
  is no longer shown as customer-facing configuration.

## Candidate verification

- JavaScript and Ruby syntax, Worker configuration synchronization, and
  `git diff --check` passed.
- The focused post-event unit suites passed 23 tests. The complete unit suite
  passed 493 tests across 102 files.
- The focused admin browser suite and the complete host browser suite passed;
  the complete suite covered 42 tests at desktop and narrow-screen widths.
- The host security suite passed all 22 tests.
- Production Jekyll build and minification passed. Performance budgets passed
  at 509,645 JavaScript bytes and 196,280 CSS bytes; `admin.css` remains
  114,698 of 115,000 bytes because feature styling is lazily loaded.
- Local `npm run test:premerge` completed phases 1–7. Its Podman phase could
  not start because another project's VM owned the machine's single Apple
  virtualization slot; that unrelated VM was left undisturbed. Protected
  **Merge Smoke** is required on the exact candidate commit before merge and
  supplies the containerized pre-merge gate.

## Ethical review

- The preview remains authenticated, recipient-free, sandboxed, and based only
  on sample-event and unsaved configuration data.
- Separate authored language fields avoid presenting machine-generated copy as
  approved translation.
- Delivery audience, deduplication, suppression, cutoff, and idempotency rules
  are unchanged. No attendee names, registration answers, order tokens, ticket
  links, or fulfillment data enter the email.

## Release sequence

1. Push the candidate branch and require protected **Merge Smoke** on the exact
   commit.
2. Merge the reviewed candidate to `main`, create immutable tag `v1.3.2`, and
   dispatch **Deploy Production** with that tag.
3. Verify the deployed Worker version/configuration, new public preview assets,
   public Store pages, private admin response policy, and production posture.
4. If acceptance fails, redeploy immutable tag `v1.3.1`; do not roll back
   canonical orders, fulfillment, inventory, or email delivery state.
