## Incident evidence and root cause

- The canonical repository still contained Film Fatale as `status: "active"`,
  proving the reported 502 was a failed save rather than delayed catalog
  propagation.
- A live production tail captured Worker version
  `81f6a2f8-ee6c-43d9-b8de-36160d7a473f` accepting the authenticated publish
  request, then failing all three reads of
  `_products/film-fatale-at-the-guild-cinema.md` with status 502 before any
  write attempt.
- The three attempts completed in under one second. A minimal Wrangler Worker
  using the production compatibility date reproduced the exact cause: the
  runtime rejects Fetch `redirect: "error"` immediately and requires manual
  redirect handling at the edge.
- GitHub reported its API operational during the incident. The configured
  production secret inventory included the GitHub token, owner, repository,
  ref, and workflow names; no secret values were read or exposed.

## Fix and safety properties

- Platform PR #37 released `@dustwave/worker-core` 0.12.1 and Platform v0.34.1.
  The GitHub client now requests `redirect: "manual"`, cancels any 3xx body,
  returns a bounded `github_redirect_rejected` failure, and never follows or
  returns the redirect location.
- Store pins the immutable Platform release and retains its existing bounded
  transient-read retries, ambiguous-write reconciliation, optimistic SHA
  conflict handling, repository authority, and rebuild trigger.
- Worker GitHub error logs now include the bounded shared failure code beside
  the status without logging response bodies, credentials, or redirect targets.
- The real Film Fatale product was not mutated during diagnosis or release
  verification. Archiving it remains an explicit administrator action.

Production deployment must use the immutable reviewed `v1.2.2` tag. Verify the
deployed Worker version and perform a read-only repository-backed admin action
