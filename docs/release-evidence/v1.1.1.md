The platform delta is additive for Store's consumed Turnstile, tax, QR,
dirty-control, tab, and credentialed-download seams. Store continues to own
catalog data, checkout, payments, orders, inventory, fulfillment, customer
access, configuration, storage, secrets, and deployment. A new test verifies
the exact gitlink, canonical HTTPS remote, package versions, and every raw
shared source path Store imports or serves.

The release also closes two pre-existing operational gaps found during this
upgrade. Generated production JavaScript now minifies local identifiers while
preserving public globals, and the actual generated asset budget runs in the
pre-merge build gate. Deployment setup dry-runs now plan secret names without
prompting for or passing secret values. The generated catalog snapshot was
refreshed from canonical product sources; its diff changes descriptions and
the source hash only, not identifiers, SKUs, prices, inventory, tax,
fulfillment, or availability.

The same `v1.1.1` release line also corrects public inventory freshness. An
inventory-tracked home or product page now makes one non-blocking request per
navigation to a sanitized projection of confirmed availability. The response
contains only public SKU keys and `available`, uses a fixed-key 15-second
browser/Workers Cache policy without stale serving, and performs no order scan
or Durable Object request. Static catalog counts remain the no-JavaScript or
network-failure fallback. Cart validation and checkout remain authoritative
and continue to include active reservations.

## Security, Performance, Accessibility, And Ethical Review

- **Money and order truth:** no pricing, checkout, Stripe mutation, webhook,
  canonical inventory, order, or fulfillment policy changed. Public pages now
  read confirmed availability from an existing derived projection, while
  checkout retains reservation-aware authority. Automated verification
  created no additional test or live purchase.
- **Secrets and privacy:** no secret value is committed or captured in
  evidence. Production posture consumes Wrangler secret names only. Admin and
  customer routes retain their authentication, authorization, CSRF, noindex,
  private/no-store, and bounded-error contracts.
- **Performance:** generated JavaScript is 371,306 bytes smaller than the
  previously measured build. Minification preserves browser global names, and
  the real generated build now fails pre-merge if committed budgets regress.
  Inventory-tracked catalog pages add one non-blocking request per navigation,
  share one response across all cards and variants, never poll, and use a
  bounded 15-second browser and edge cache.
- **Responsiveness and accessibility:** the existing single-worker browser
  suite passed 34/34 across desktop, tablet, mobile, keyboard, reduced-motion,
  and 200% text-scale scenarios. Shared admin-shell focus behavior is covered
  by both platform and consumer suites.
- **Data and messaging:** no storage family, retention rule, provider, send
  path, or analytics surface changed. The new public response is allowlisted
  to catalog SKUs and `available`; it excludes limits, claims, reservations,
  product metadata, orders, customers, and admin state.
