## Behavior and security contract

- Required production secret names, Worker bindings, canonical origins, and
  runtime configuration remain the Production Posture pass/fail gate.
- Optional Stripe, Resend, and USPS probes that lack CI credentials or tools
  remain visible as `manual` / not run. Their absence is not interpreted as a
  provider failure or as proof that the provider API was contacted.
- An attempted provider check that returns `FAIL`, or a provider command that
  exits unsuccessfully, still fails the final workflow gate and opens or
  updates the sanitized posture issue.
- Provider evidence remains read-only and excludes secret values, customer
  data, and provider mutations.

- The change narrows an operator-reporting ambiguity without changing provider
  credentials, runtime secrets, customer data, checkout, fulfillment, or email
  behavior.
- Secret-name presence is treated only as configuration evidence. The workflow

  run.
- Explicit provider failures remain blocking so the change does not hide a
  provider response or weaken an existing security boundary.
