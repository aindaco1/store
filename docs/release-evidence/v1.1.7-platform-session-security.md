# Store v1.1.7 / Platform v0.17.0 session-security migration evidence

## Immutable input and boundary

- Previous Store release: `v1.1.6`.
- Platform pin: `v0.17.0` commit
  `3a526defd21d692292c73652966a044167f881d7`.
- Worker Core: `0.8.0`.

Store consumes only bounded signed-token, cookie-serialization, and same-origin
request mechanics. Store retains secret selection, normal and notification
login/session TTL selection, nonce and session records, one-time consumption,
roles and scopes, CSRF tokens and header names, routes, rate limits, storage,
credentials, email, deployment, and rollback.

## Characterization and hardening

- Existing one-time notification-link, shortened-session, session-review,
  redacted-history, CSRF/origin, role/scope, and revocation tests were retained.
- A characterization-only commit locked the exact HTTPS cookie name, path,
  `HttpOnly`, `SameSite=Lax`, `Max-Age=1800`, and `Secure` notification shape.
- The consumer migration rejects extra token segments before consuming the
  one-time nonce. Platform additionally bounds token, payload, secret, cookie,
  and claim-policy input.

## Required release evidence and rollback

- The full pre-merge gate passed: 425 unit tests and 34 browser tests passed,
  with every secret, content, i18n, syntax, focused regression, build-artifact,
  security, Podman resource, Worker, and browser phase green.
- Root and Worker production dependency audits reported zero vulnerabilities;
  the production Wrangler configuration bundled successfully in dry-run mode.
- A protected pull-request smoke remains required after Platform `v0.17.0`
  and preceding Store releases are merged.
- Roll back one Store commit and restore the v1.1.6 Platform pointer. Every
  other consumer retains its own exact pin and needs no rollback.
