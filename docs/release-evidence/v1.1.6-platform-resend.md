# Store v1.1.6 / Platform v0.16.0 Resend migration evidence

## Immutable input and boundary

- Previous Store release: `v1.1.5`.
- Platform pin: immutable `v0.16.0` commit
  `d075c3e1a29134d3ba6e4631b76dc63212347d14`.
- Worker Core: `0.7.0`.

Store consumes only bounded raw-body Resend/Svix signature verification, the
provider-error metadata shape, and pure retry disposition. Store retains the
Resend fetch, provider payloads, templates, recipients, consent, idempotency
keys, durable outbox, attempt budget, retry scheduling, webhook route/event
parsing, delivery journal, suppression effects, credentials, and deployment.

Platform contains no Store credential, recipient, product content, provider
payload, environment ID, storage binding, or deployment authority.

## Characterization and hardening

- A test-only commit first fixed the current multiple-`v1`, stale timestamp,
  malformed-secret, exact-body, 429 `Retry-After`, and permanent-bounce
  behavior before the implementation moved.
- The local adapter preserves Store's valid and mismatch response shapes and
  maps malformed timestamps to the established outside-tolerance result.
- Platform additionally bounds event IDs, signatures, and configured secret
  input and rejects fractional timestamps before HMAC work.
