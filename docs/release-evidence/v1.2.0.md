## Scope and boundaries

- Registration is opt-in for repository-backed `rsvp` products with an
  explicit `event_details.registration` block. Physical, digital, ticket,
  service, and unconfigured RSVP products retain their existing paths.
- A shared Worker normalizer owns product publication, checkout validation,
  canonical response snapshots, roster projections, check-in, and CSV export.
  Browser normalization is presentation-only; the Worker re-resolves current
  product data and remains authoritative.
- Guest names and custom answers remain in memory before checkout and are not
  written to local or session storage. Answers are omitted from email, Stripe
  metadata, logs, and public catalog data.
